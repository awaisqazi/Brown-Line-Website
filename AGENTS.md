# Project Working Notes

These instructions apply to the whole repository.

## Documentation Habit

After taking actions in this project, update the docs wherever the change makes the docs more useful later.

- Update `design.md` for changes to UI, styling, interaction patterns, page structure, component behavior, infrastructure, deployment, data flow, or public project conventions.
- Update `PRIVATE_README.md` for sensitive or operational details such as passwords, keys, local env values, private runbooks, troubleshooting notes, migrations, recovery procedures, and deployment gotchas.
- Keep secrets and credential material out of tracked files. `PRIVATE_README.md` is intentionally ignored by git.
- Do not force a docs edit when nothing meaningful changed, but treat these docs as part of the definition of done whenever relevant.
